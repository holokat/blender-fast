What this comparison measures

Runs execute sequentially on one GPU to avoid resource competition. The total includes setup, bridge edits, validation, saving, renderer startup, one first render and three warm repeat renders. Model authoring and preview preparation are excluded.

The baseline uses 250 ms active polling and one object per request. The optimized lane uses up to 50 ms active polling and batches of 64, preserving existing faster settings. Both render with the same GPU backend, geometry, camera, lights, 64-sample limit and 1400 × 1000 output. The optimized lane also uses GPU denoising and persistent data.

Persistent data retains reusable scene data within a process and uses extra memory. First-render timings are the first in each process, not a guarantee of a cold GPU driver cache. Profiles run in baseline-then-optimized order; system load and thermal effects are uncontrolled. Live construction updates follow acknowledged Blender requests. Render images update when a render finishes, not per sample.
